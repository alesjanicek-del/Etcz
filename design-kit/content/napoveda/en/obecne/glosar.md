# Glossary

Terms used in the app and how they match the terms in the tender documentation.

## Terms used in the app

| Term | Meaning |
|---|---|
| Organisation | The customer that uses the app, for example a public authority. |
| Branch | An organisational unit of the organisation. Keeps tests, print batches and results of different workplaces apart. |
| Active branch | The branch selected in the top bar. New records are created in it, and the Print page shows only its batches. It does not filter results. |
| Organisation administrator | Manages the settings, branches, users and data of the whole organisation. |
| Branch administrator | Manages the users and groups of their branch. |
| Instructor | Builds tests, delivers them and evaluates them. |
| Question author | Creates and edits questions in question banks. |
| Learner | A person with an account who can be assigned a test. |
| Test taker | Anyone taking a test, with or without an account. |
| Supervised in-room exam participant | A test taker who joined with the code from the projector screen. People in the room and in the waiting room are called “participants” before the test starts; after it starts, they are test takers. See [Supervised in-room exam with a waiting room](../lektor/prezencni-zkouska.md). |
| Question bank | A named group of questions with assigned permissions. |
| Question and question version | Every change to a question’s content creates a new version. Submitted attempts keep their version. |
| Tag and tag list | A way to sort questions. Tag lists have a scope: organisation, branch, instructor or question bank. |
| Test | The exam specification: sections, question selection rules and settings. |
| Test section | A selection of questions from one question bank. |
| Required and excluded question | Every test taker gets a required question; an excluded question is never selected. |
| Allowed and blocked tags | A filter for the questions that are drawn at random. |
| Test version | A specific selection and order of questions and answers for one test taker or one printed sheet. |
| Unique test version | A test version with a different selection of questions, a different question order or a different answer order (depending on the shuffle settings). The app prefers question selections that nobody has had yet. |
| Test assignment | One delivery of a test in a specific way: supervised in-room exam, codes, assigned to a group, link or print. |
| Supervised in-room exam | An exam in a room, with a code and QR code on the projector screen and a waiting room. |
| Access code | A test taker’s personal code for opening the test. |
| Handover code | A one-time code from the instructor for continuing on another device. Valid for 10 minutes. |
| Test password | A shared password for starting the test. It is optional, and the instructor gives it out. |
| Link | Anonymous access to a test. One test can have several links, each labelled with its purpose. |
| Attempt | One person taking a test once. |
| Official test | A mode for official exams: no links, no feedback and no correct answers shown. |
| Print batch | Test versions for printing, with answer sheets and answer keys. |
| Answer sheet, answer key, scoring table | Printouts for a paper exam. |
| Grading method | The rule that decides whether a test taker has passed the test (percentage, points, grades). |
| Result report | A PDF record of an attempt with a verification code. |
| Verification code | The code on a result report that anyone can use to verify it is genuine. |
| Live monitor | Real-time view of an exam in progress. |
| Trial run | An instructor taking the test to try it out. It does not count. |
| Record protection (legal hold) | A block on anonymising a record, for example because of an appeal. |
| Customer’s authorised representative | The person who submits support requests on behalf of the organisation. |
| 2FA | Two-step verification: a password and a code from your phone. |
